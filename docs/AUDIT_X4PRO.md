# AUDIT_X4PRO.md — BookPoint на Xteink X4 Pro, полный аудит состояния

Дата: 11.09.26. Версия прошивки: 2.0.0-bookpoint-x4pro (сборка 5.68 МБ, RAM 19.9%).
Этот документ — сводка всего, что известно про X4 Pro в контексте BookPoint:
железо, что уже сделано, что сломано или отложено, риски, выводы ресёрча 4PDA
и дорожная карта. Дополняет AUDIT_MAXIMAL.md (аудит 18 прошивок) — там общая
база, здесь только X4 Pro.

---

## 1. Железо X4 Pro (проверено на реверсе + подтверждено на живых устройствах)

Источник: freeink-sdk `libs/hardware/BoardConfig/include/BoardConfig.h`,
профиль `XTEINK_X4_PRO` (строка 1558), плюс сводка Alpa4hinO (пост 4PDA #7352).

| Узел | Детали |
|---|---|
| MCU | ESP32-S3, 16 МБ flash, 8 МБ PSRAM |
| Экран | 800x480, контроллер зависит от партии: SSD1677 (по умолчанию), UC8179 или UC8279; определяется при загрузке (`applyXteinkDisplayController`) |
| Экран SPI | SCLK=12, MOSI=11, CS=13, DC=18, RST=14, BUSY=6; 10 МГц |
| Кнопки | Только 3, цифровые, активные LOW: Left/Up=GPIO0, Right/Down=GPIO7, Power=GPIO3 (GPIO0 — boot-strap, нельзя держать при ресете) |
| Сенсор | GT911 на общей I2C SDA=39/SCL=38, адрес 0x5D (alt 0x14), INT=GPIO10 (активный HIGH), RST=GPIO4, питание GPIO2 (активный LOW); смонтирован портретно, swapXY+flipY |
| Home key | Ёмкостная клавиша через GT911 (hasHomeKey=true) — заменяет back/confirm кнопок |
| Подсветка | Двухканальная тёплая/холодная LEDC PWM: холодная GPIO8 (ch4), тёплая GPIO9 (ch5), 25 кГц / 10 бит, активные HIGH |
| SD | Нативный SDMMC 1-bit: CLK=41, CMD=42, D0=40, 40 МГц; питание GPIO5 (активный LOW, карта работает при удержании LOW) |
| Батарея | CW2017 по I2C 0x63 (та же шина); заряд STAT=GPIO21, активный HIGH; ADC-пина нет |
| RTC | BM8563 (PCF8563-совместимый) по I2C 0x51, та же шина |
| USB | USB-OTG (S3), MSC/VBUS-детект: GPIO10 — кандидат, не подтверждён |
| Мастер-рейл | GPIO1 (power.latch0): питает панель и SD-слот, держится HIGH |

Ключевые отличия от X4/X3 (C3): кнопки цифровые, а не ADC-лестница; есть
сенсор, подсветка, PSRAM; нет проблемы GPIO13 battery latch (на X4 Pro 13 —
это CS дисплея, SDK отклоняет такой latch через `latchConflictsWithBus`).

## 2. Конфигурация сборки

`platformio.ini`, env `x4pro` (основной, `default_envs`) и `x4pro-gh_release`:

- `esp32-s3-devkitc1-n16r8`, `dio_opi`, `BOARD_HAS_PSRAM`, `FREEINK_FB_PSRAM=1`
  — фреймбуфер в PSRAM
- `FREEINK_DEVICE_X4PRO=1`, `USE_BLOCK_DEVICE_INTERFACE=1` (SDMMC через block device)
- `USB_PRODUCT="BookPoint_X4_Pro"`, `ENABLE_SERIAL_LOG` (+`CROSSPOINT_WAIT_FOR_USB_SERIAL` в dev)
- **`FREEINK_FRONTLIGHT_LS`** — LEDC-каналы подсветки собираются с
  `LEDC_SLEEP_MODE_KEEP_ALIVE`: PWM продолжает управлять GPIO8/9 во время light
  sleep (SDK держит RC_FAST живым, пока свет горит, через
  `esp_sleep_sub_mode_config(ESP_SLEEP_DIG_USE_RC_FAST_MODE, lit)`). Благодаря
  этому горящая подсветка НЕ блокирует idle light sleep и не мерцает.
- Версия в сборке: `{version}-x4pro`, например 2.0.0-x4pro.

Ловушки сборки (проверено на практике):
- путь проекта без пробелов; ESP-IDF не собирается из Git Bash (MSYSTEM сбрасывается
  в build.bat); `pio run | tail` маскирует код выхода
- после обновления сабмодуля freeink-sdk удалять `.pio/libdeps` (мусорные копии
  с Windows-симлинков)
- `gen_i18n.py`: YAML без комментариев; каждый STR_* из кода обязан быть в english.yaml

## 3. Что уже работает на X4 Pro (состояние на 11.09.26)

Чтение и ядро:
- EPUB 2/3, TXT (с детектом кодировок CP1251/KOI8-R/CP866), XTC/XTCH
- Сноски внизу страницы — универсальный экстрактор (исправлен поиск якоря
  `id="..."`, целые элементы, отсев обратных ссылок), проверен на реальных книгах
- Статистика чтения (ленивое накопление, CSV-снапшоты, импорт из inkMOD),
  экраны статистики, сетка 3x2, dashboard
- Быстрое листание, очередь нажатий
- Словари StarDict + скачивание RU-EN/EN-RU по Wi-Fi
- Клиппинги, темы (Classic/Lyra/Minimal/Dashboard и др.), игры (2048/Сапёр/Шахматы)

X4 Pro-специфика:
- Подсветка: панель по свайпу от верхнего края (яркость+теплота живьём),
  **двойное нажатие Power включает/выключает свет**
  (`handleX4ProFrontlightDoubleClick`, main.cpp:216), состояние и яркость
  запоминаются, restore on wake
- Сенсор: GT911 работает, режимы в читалке: тапы/свайпы/инвертированные/выкл
  (`touchReaderControls`), тап по центру открывает меню, Home key
- Часы в строке состояния читалки (слева/справа) — прямой ответ на пост #9114
  (в CrossInk часы только сверху по центру и съедают строку)
- Автономность: Wi-Fi auto-off 3 мин, ленивая статистика без фоновых задач,
  экран Автономность, журнал батареи, `lastKnownEpoch` в state
- Экраны сна со статистикой уже есть (renderReadingStatsSleepScreen: серия,
  время, календарная тепловая карта)
- USB Drive: **временно убран из x4pro-сборки** (FREEINK_CAP_USB_MSC снят —
  TinyUSB MSC требует пересборки core с конфигом; вернуть отдельной задачей)

## 4. Новое за эту ночь: light sleep race-to-sleep (пункт 1 дорожной карты)

Реализовано, собрано, **выключено по умолчанию** (настройка Настройки → Система →
"Спящий режим простоя (X4 Pro)" / `lightSleepIdle`, default 0).

Механика (порт witchhunt `HalPowerManager::lightSleep` под X4 Pro):
- После 1000 мс бездействия idle-цикл вместо `delay(50)` на пониженной частоте
  спит слайсами по 50 мс (`esp_light_sleep_start`), пробуждения — таймер + GPIO
- Источники пробуждения: GPIO0/7/3 (кнопки, уровень LOW) и GPIO10 (INT тача,
  HIGH) — цифровые кнопки X4 Pro дают мгновенное пробуждение, чего нет на C3
  (там witchhunt вынужден опрашивать по таймеру); пин, уже лежащий на уровне
  пробуждения (палец на кнопке), не вооружается — иначе шторм
- Отказы от слайса: активен HalPowerManager::Lock (рендер), Wi-Fi не выключен,
  USB подключён, ввод в дебаунсе (`isDebouncePending` — новое passthrough в
  HalGPIO), не X4 Pro
- Горящая подсветка НЕ блокирует слайсы: в x4pro-сборке LEDC собран с
  KEEP_ALIVE (FREEINK_FRONTLIGHT_LS), PWM живёт сквозь light sleep; предостережение
  witchhunt про мерцание относится к обычным LEDC-сборкам
- После сна: `xTaskCatchUpTicks(sleptMs)` — FreeRTOS tick корректируется
  (esp_timer millis() честен сам)
- Разоружение wake-источников полное: `ESP_SLEEP_WAKEUP_ALL` +
  `gpio_wakeup_disable` + `GPIO_INTR_DISABLE` (безопасно — InputManager чисто
  поллинговый, ISR нет); иначе таймерный wake протёк бы в deep sleep
- **Пад-холды для рейлов (GPIO1/GPIO5/GPIO2) сознательно не ставятся**: в light
  sleep цифровые пады держат уровень нативно, а забытый gpio_hold_en молча
  ломает все последующие digitalWrite на паде — хуже теоретической просадки.
  Вернуться к вопросу только с доказательствами с устройства (SD отваливается,
  сенсор умирает после простоя)
- Попутно найдено и исправлено: **park()/releaseOnWake() подсветки нигде не
  вызывались** — при глубоком сне LED-пады оставались запитанными (утечка
  quiescent-тока всю ночь, crosspoint#3215). Теперь `Frontlight.park()` в
  enterDeepSleep до снятия рейлов, `Frontlight.releaseOnWake()` при загрузке
  до begin(); оба passthrough добавлены в HalFrontlight под `#ifdef FREEINK_FRONTLIGHT_LS`

Файлы: lib/hal/HalPowerManager.h/.cpp (`tryLightSleepSlice`,
IDLE_LIGHT_SLEEP_MS=1000, LIGHT_SLEEP_SLICE_MS=50), lib/hal/HalGPIO.h/.cpp
(`isDebouncePending`), src/main.cpp (idle-ветка + park/releaseOnWake),
src/CrossPointSettings.h (`lightSleepIdle`), src/SettingsList.h (тумблер,
STR_CAT_SYSTEM), lib/I18n/translations/{english,russian}.yaml (STR_LIGHT_SLEEP_IDLE).

Риски и что проверить на устройстве (в порядке важности):
1. Ночной расход с включённой настройкой vs без (журнал батареи уже пишет %)
2. Реакция кнопок/тача после простоя: не теряется ли нажатие, жив ли тач
3. SD-карта после долгого простоя: не требует ли ремоунта
4. Подсветка: не мигает ли на границах слайсов при низкой яркости
5. Скользящий кейс: Power-клик для засыпания во время слайса

## 5. Ресёрч 4PDA: вердикты владельцев X4 Pro (полностью в docs/TOPIC_RESEARCH.md)

Хронология: анонс 10.05.26 (#1571) → продажи с 21.07.26 → бета CrossPoint 23.07.26
(#5236) → CrossInk RC с Pro в августе → разблокировка залоченных через OTA
Unlocker с конца августа → массовые вердикты в сентябре.

Чего просит сообщество (по постам):
1. **Подсветка** — боль №1: "мало настроек для Pro", неудобное управление,
   жалобы на неработающий градиент теплоты (#9681), пропадание света под
   CrossPoint (#9664). Кнопочные комбинации для света (#5237) — уже сделано
   (двойной Power)
2. Больше назначений клавиш (#9042, #9114) — у CrossInk богаче
3. Часы в строке состояния (#9114) — уже сделано
4. Режимы сенсора (#7198) — уже есть
5. Автономность: 5%/сутки во сне на CrossInk (#9297) — наше поле
6. FB2/FB2.zip: 734 упоминания в теме, но пользователь BookPoint прямо просил
   FB2 не делать — вне дорожной карты
7. README с инструкцией для залоченных Pro — сделано (точка доступа crosspoint,
   пароль 11111111, попытки с 5-й, Xteink Unlocker, SD-обновление)

Железные факты от владельцев, влияющие на прошивку: контроллер дисплея плавает
по партиям (SSD1677/UC8179/UC8279 — автоопределение обязательно, SDK умеет);
UC8279d встречается на свежих ревизиях (пост #7879); тач GT911 и подсветка
двухканальные.

## 6. Открытые вопросы и долги по X4 Pro

1. **USB Drive (MSC)** — отложен: нужен TinyUSB core config без пересборки ядра.
   Изучить, как upstream x4pro включает MSC на том же prebuilt core
2. **Light sleep**: измерить на устройстве (раздел 4), потом решать про default on
3. **Градиент теплоты** — проверить на живом Pro (жалобы #9681/#9664): 0..100
   warm/cool mix через FrontlightManager
4. Назначения клавиш: у нас sideButtonLayout + longPressMenu, но меньше свободы,
   чем у CrossInk — рассмотреть quick actions на длинные нажатия
5. Слоты прошивок (dual-bank) — community-просьба, вне ближайшего плана
6. UC8279d поддержка — контролируется SDK при загрузке; держать сабмодуль свежим
7. Прошивка залоченных Pro: подтвердить, что BookPoint.bin ставится штатным
   SD-путём после анлока (пользователь ещё не проверял на своём устройстве)
